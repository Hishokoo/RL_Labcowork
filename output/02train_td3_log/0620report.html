02train_td3.py Reward Shaping 除錯記錄

記錄日期：2026-06-20　目的：解決 Ant-v5 TD3 訓練「衝出邊界」與「走路太快」的問題

目錄： 問題背景 第一輪修改 使用者質疑與反思 第二輪：靜止懲罰實驗 第三輪：簡化 reward 目前結論 目前程式碼狀態 下一步選項

問題背景

使用者打開 02test_td3.py 模擬器，發現用 output/02train_td3 訓練出來的模型：

  1. 會跑出邊界（地圖外）
  2. 走路速度太快，懷疑這導致牠用蠻力衝刺而不是用重心轉移、抬腳的自然步態行走

原始 02train_td3.py（修改前）已經有邊界懲罰跟動作正則化，但效果不夠。

原始程式碼問題診斷

問題說明
Bootstrap bug 邊界截斷時只設 truncated=True，存進 replay buffer 的 terminal flag 只用環境原生的 terminated。 代表 critic 在算 TD target 時，仍認為「衝出邊界」這個狀態後面還有正常的未來價值可以 bootstrap，邊界懲罰訊號被沖淡。
懲罰太晚太小 MAX_RADIUS=8.0 給的空間大，懲罰只在超出後才出現（係數僅 1.0），相對 Ant-v5 整個 episode 累積的 forward_reward，這懲罰量級太小、且沒有漸進梯度讓牠提早轉向。
沒有直接的速度控制 原本只懲罰動作幅度跟抖動，沒有針對「速度」本身。Ant-v5 預設 forward_reward_weight=1.0，本質上鼓勵用最大 x 方向速度衝刺。

第一輪修改：邊界修正 + 速度區間懲罰

修改內容

  • 邊界出界同時標記為 terminal（修正 bootstrap bug）：replay_buffer.add(..., float(terminated or boundary_violation))
  • 加入 SOFT_RADIUS=6.0 漸進式邊界懲罰，MAX_RADIUS=8.0 才強制截斷
  • BOUNDARY_PENALTY 從 1.0 加大到 5.0
  • 用 Ant-v5 原生參數 forward_reward_weight 從 1.0 降到 0.5（後調整為 0.6）
  • 加入速度區間懲罰：MIN_SPEED=0.5、TARGET_SPEED=1.5，低於下限或高於上限都扣分
  • ACTION_PENALTY_WEIGHT 從 0.5 降到 0.15（避免跟 Ant-v5 內建 ctrl_cost_weight=0.5 重複扣分）

使用者質疑與反思

使用者：「我剛剛不是有請你模擬計算會不會站著不動嗎」

反思：事前的 reward 地形模擬只驗證了「reward function 設計方向對不對」（用既有會走的策略去算分數），並沒有模擬「一個從零開始、權重隨機初始化的 TD3 agent，實際訓練時會不會自己找到這個會走路的解」。這是兩個完全不同的問題：

  1. reward 地形對不對（驗證過，是對的）
  2. 訓練過程能不能找到地形上的最優點（探索/收斂問題，沒辦法只靠靜態模擬預測）

實際訓練時，agent 一開始就發現「幾乎不動」可以穩穩拿到 healthy_reward，這是一個很容易達到、風險很低的局部解，比起冒險走到 reward 更高的「走動區」（會經歷不熟練、容易摔倒的過渡期）更有吸引力。

第二輪：嘗試加重「站著不動」的懲罰

實驗 A：weight=3.0，從零訓練，100k steps

把 STILLNESS_PENALTY_WEIGHT 從 0.5 加到 3.0（讓站著不動的 reward 從 0.867 降到理論值 0.218，遠低於走動的 0.99）。

對照T=100,000 時 episode 狀態
weight=0.5（第一輪結果）穩定跑滿 1000 步，reward 530~580
weight=3.0episode 縮短到 7~65 步，reward 持續負值（-15~-120），agent 頻繁摔倒

逼牠不能站著不動，但牠還沒學會邊走邊平衡。

實驗 B：weight=1.5，從零訓練，延長到 300k steps

T=50,000T=100,000T=150,000~300,000
短暫穩定，episode 跑滿 1000 步，reward 轉正（108~136），但 vx 仍很低（0.04~0.06）又變得不穩定，episode 縮回 8~230 步，reward 轉負完全卡住，episode 長度死死卡在 7~9 步，整整 15 萬步沒有任何改善

結論：weight=1.5 在 300k steps 內沒有收斂的跡象，agent 學會的是「猛衝一下拿到還不錯的速度，然後立刻摔倒重來」，而不是真正穩定走路。

實驗 C：weight=1.5，從舊的「會走但太快」模型微調（fine-tune），100k steps

嘗試用 output/01train_td3 的已訓練模型（知道怎麼協調腳走，但不知道要減速/守邊界）作初始化，而非從零訓練，理論上應該更快收斂。

結果：從頭到尾都不穩定，到 T=100,000 時 episode 仍只有 7~9 步，幾乎每次都摔。新的 reward 分佈跟舊模型訓練時差太多，等於要它「一邊忘記舊習慣一邊學新規則」，反而比從零訓練更不穩。

第三輪：簡化 reward，只留邊界 + forward_reward_weight

判斷問題不在 stillness 權重該調多少，而是同時疊加太多懲罰項（邊界 + 速度上限 + 速度下限 + 動作幅度 + 動作差異，還沒算 Ant-v5 內建的 forward/healthy/ctrl/contact）讓 reward 地形太複雜。改為：

  • 移除 MIN_SPEED / TARGET_SPEED / SPEED_PENALTY_WEIGHT / STILLNESS_PENALTY_WEIGHT 整組速度懲罰
  • ACTION_PENALTY_WEIGHT 還原回原始的 0.5
  • 保留：邊界 bootstrap bug 修正、SOFT_RADIUS/MAX_RADIUS/BOUNDARY_PENALTY、ACTION_DIFF_PENALTY_WEIGHT
  • 只靠調整 FORWARD_REWARD_WEIGHT 來抑制衝刺速度

實驗 D：FORWARD_REWARD_WEIGHT=0.6，簡化版，150k steps

目前結論

6 次實驗一致指向同一個結論：

#設定結果
1weight=0.5/0.6 + 弱 stillness(0.5) + 速度區間懲罰穩定但幾乎不走（vx≈0.00~0.02）
2weight=0.6 + 強 stillness(1.5/3.0)，從零訓練不穩定，反覆摔倒，不收斂
3weight=0.6 + 強 stillness(1.5)，從舊模型微調更不穩定，摧毀原有技能
4weight=0.6，無速度懲罰（簡化版）穩定但幾乎不走（vx≈0.03~0.09）
5weight=0.8，無速度懲罰（簡化版）穩定但持續退化到不走（vx 持續下降）

在 forward_reward_weight 0.5~0.8 這個範圍內，不管要不要加 stillness 懲罰、懲罰強或弱，vanilla TD3 + Ant-v5 都會被吸進「站著領 healthy_reward」這個局部最優解。這不是單純調參數能解決的問題，是 reward 結構本身的吸引盆地（attractor basin）問題。

唯一確定有效、且在所有實驗中都穩健運作的部分：邊界懲罰機制（SOFT_RADIUS 漸進懲罰 + MAX_RADIUS 強制截斷 + bootstrap bug 修正）。在所有 6 次實驗中，agent 從未真正衝出邊界，距離都被控制在安全範圍內，且在 weight=0.8 的實驗中可以看到 episode 精準在 dist=8.00 截斷，證明機制運作正常。

目前程式碼狀態（02train_td3.py）

FORWARD_REWARD_WEIGHT = 0.8     # Ant-v5 原生前進獎勵權重（預設 1.0；0.6 太弱會讓 agent 學成幾乎不走）
SOFT_RADIUS           = 6.0     # 超過此距離開始給漸增邊界懲罰
MAX_RADIUS            = 8.0     # 離原點距離超過此值強制截斷 episode
BOUNDARY_PENALTY      = 5.0     # 邊界懲罰係數
ACTION_PENALTY_WEIGHT = 0.5     # 動作幅度懲罰係數（已還原為原始值）
ACTION_DIFF_PENALTY_WEIGHT = 0.1  # 相鄰動作差異懲罰係數

...
# 邊界位置懲罰：超過 SOFT_RADIUS 後漸增懲罰，超過 MAX_RADIUS 強制截斷
dist = info["distance_from_origin"]
if dist > SOFT_RADIUS:
    reward -= BOUNDARY_PENALTY * (dist - SOFT_RADIUS)
boundary_violation = dist > MAX_RADIUS
if boundary_violation:
    truncated = True

# 動作正則化
reward -= ACTION_PENALTY_WEIGHT * np.sum(np.square(action))
reward -= ACTION_DIFF_PENALTY_WEIGHT * np.sum(np.square(action - prev_action))

# Store transition：出界視為 terminal，讓 critic 學到「出界=沒有未來」
replay_buffer.add(obs, action, next_obs, reward, float(terminated or boundary_violation))

注意：output/02train_td3/ 目前的 checkpoint 仍是「實驗 1」（weight=0.6 + 弱 stillness）跑完整 1M steps 的結果，尚未用上面這組設定重新跑過完整訓練。所有 0.8 / 1.5 / 3.0 的實驗都只在 /tmp/validate_stillness/ 做短時間驗證，沒有覆蓋正式輸出目錄。

下一步選項

選項說明預期效果
A. Curriculum（建議） 訓練前期 forward_reward_weight 設高（如 1.0，先學會走路這個技能），訓練後期逐漸降低（如降到 0.6），讓 agent「先學會走、再學會放慢」，而非一開始就同時面對矛盾目標。需修改 training loop 加入隨 timestep 變化的權重。 最有機會同時解決「會走」+「不要太快」，但需要再開發 + 驗證一輪
B. 接受 weight=0.8 的結果 不出界但幾乎不走，直接跑完整 1M steps。 解決邊界問題，但走路目標沒達成
C. 還原 forward_reward_weight=1.0 只靠已修正的邊界機制擋住出界，不刻意壓低速度。 大概會走得跟原來一樣快，但理論上不會出界
