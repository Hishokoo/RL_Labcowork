背景

使用者打開 02test_td3.py 模擬器，發現用 output/02train_td3 訓練出來的模型：

  1. 會跑出邊界（地圖外）
  2. 走路速度太快，懷疑這導致牠用蠻力衝刺而不是用重心轉移、抬腳的自然步態行走

原始程式碼已有邊界懲罰跟動作正則化，但效果不夠。本日誌記錄修正過程中所有嘗試、驗證數據與結論。

確定的程式碼修正（已套用到 02train_td3.py）

修正項目說明
Bootstrap bug 原本出界只設 truncated=True，存進 replay buffer 的 terminal flag 沒有把邊界截斷算進去，導致 critic 在 bootstrap 時仍認為出界後有未來價值，懲罰訊號被沖淡。改為： 
replay_buffer.add(obs, action, next_obs, reward,
                  float(terminated or boundary_violation))
漸進式邊界懲罰 新增 SOFT_RADIUS=6.0 在接近邊界時就給漸增懲罰，MAX_RADIUS=8.0 才強制截斷（原本只有事後線性懲罰，沒有提早的負梯度）；BOUNDARY_PENALTY 從 1.0 加大到 5.0 
dist = info["distance_from_origin"]
if dist > SOFT_RADIUS:
    reward -= BOUNDARY_PENALTY * (dist - SOFT_RADIUS)
boundary_violation = dist > MAX_RADIUS
if boundary_violation:
    truncated = True

這兩項修正在後續所有實驗中都穩健運作——agent 從未在任何一次實驗中真正衝出邊界。

嘗試過的方向（按時間序）

嘗試 1：速度區間懲罰 + forward_reward_weight=0.6（正式跑滿 1,000,000 steps）

加入 MIN_SPEED=0.5 / TARGET_SPEED=1.5 速度區間懲罰、STILLNESS_PENALTY_WEIGHT=0.5、ACTION_PENALTY_WEIGHT=0.15（避免跟 Ant-v5 內建 ctrl_cost 重複扣分）。

訓練前先用舊模型動作分布模擬 reward 地形，驗證走路（vx≈1.13）reward 比站立高（1.505 vs 0.867），地形設計本身正確。

正式訓練（約 55 分鐘）：episode 穩定跑滿 1000 步，最終 eval reward = 907.7，看起來很成功。

但實際用腳本量化驗證 5 個 episode：avg_vx 僅 0.00~0.02，max_dist 全部 < 1m —— agent 幾乎完全沒有移動，收斂到「站著不動」局部解。事前的靜態模擬只驗證了 reward 地形設計方向，並未模擬「TD3 從零訓練是否真的能找到地形上的最優點」，這是探索/收斂問題，無法只靠靜態模擬預測。

嘗試 2：加重 STILLNESS_PENALTY_WEIGHT（0.5 → 1.5 → 3.0）

設定驗證長度結果
weight=3.0，從零訓練100k stepsepisode 縮短到 7~65 步，reward 持續負值，agent 頻繁摔倒
weight=1.5，從零訓練延長到 300k stepsT=50k 短暫穩定（reward 轉正但 vx 仍低），T=100k 起又不穩定，T=150k~300k 完全卡死在 7~9 步，15 萬步沒有任何改善

逼牠不能站著不動，但牠還沒學會邊走邊平衡，反而陷入「衝一下就摔倒重來」的爛局部解，且長時間訓練也未見收斂。

嘗試 3：用舊的「會走但太快」模型微調（fine-tune）

用 output/01train_td3 已訓練模型（知道怎麼協調腳走，但不知道要減速/守邊界）作初始化，weight=1.5，100k steps 驗證。

結果比從零訓練更不穩定，從頭到尾 episode 都只有 7~9 步。新 reward 分佈跟舊模型訓練時差太多，等於要它一邊忘記舊習慣一邊學新規則，反而更不穩。

嘗試 4：簡化版 —— 移除速度懲罰，只留邊界 + forward_reward_weight

設定150k steps 結果
weight=0.6（移除所有 stillness/speed 懲罰，ACTION_PENALTY_WEIGHT 還原 0.5）穩定跑滿 1000 步，reward 830~870，max_dist 2.5~5m（安全），但 avg_vx 僅 0.03~0.09
weight=0.8穩定，但 avg_vx 隨訓練「持續下降」（T50k: 0.06~0.15 → T150k: 0.02~0.05），max_dist 同步縮小

關鍵發現：拿掉 stillness 懲罰結果幾乎一樣 —— 證明問題不是懲罰強弱，而是 Ant-v5 預設 healthy_reward=1.0 讓「站著不動」變成零風險的 attractor，在 0.5~0.8 範圍內不管怎麼調 forward_reward_weight 都會被吸進去。

嘗試 5：採用 markdown/ant_v5_attractor_fix.md 方案 —— healthy_reward=0.0 + contact_cost_weight=5e-3

診斷文件（外部 Claude 對話產出）指出根因是 healthy_reward，解法：拿掉 healthy_reward（站著不再有收入）+ 提高 contact_cost_weight 十倍（懲罰重踩蹬地，改善跑姿）+ 還原 forward_reward_weight=1.0。

階段avg_vxepisode 長度
T=0~50k已有起色（0.1~1.4 區間）變化大，多在 10~230 步
T=100k0.1~0.8（達標：md 檔要求 >0.1）卡在 8~12 步
T=150k~200k0.1~0.8，沒有再進步持續卡在 7~12 步，無改善

移動誘因確實恢復了（avg_vx 不再趨近 0），但觸發了 md 檔自己預告的「風險1：移除 healthy_reward 後 agent 學成快速摔倒結束 episode」——episode 長度在 10 萬步內完全沒有改善。

嘗試 6：依 md 檔備案調整 healthy_reward=0.0 → 0.1

md 檔建議：若觀察到 episode 長度持續 < 50，加回一點點 healthy_reward 當安全網。

設定T=100k~200k episode 長度avg_vx
healthy_reward=0.0卡在 8~12 步0.1~0.8
healthy_reward=0.1卡在 7~10 步（幾乎相同）0.3~0.8

備案未生效，跟 0.0 版本是同一種失敗模式：agent 確實會動，但完全學不會「邊走邊平衡」，摔倒懲罰太重導致牠每次都在學會走路之前就先放棄。
