Reward engineering

真正的主角是 reward 地形

演算法一直是 TD3；版本差異主要來自速度、步態、控制力與存活分數如何組合。後期實驗證明，代理指標漂亮不等於肉眼自然。

03 · Additive legacy

r = r_speed + r_alive + r_ctrl + r_gait + r_posture

r_speed=-|vₓ−1|；ctrl=−5‖a‖²；legacy gait 逐幀獎勵同對角同步。優點是密集、穩定、自然；缺點是靜止四腳著地仍有 gait 分。

04–10 · Forward gated

r⁺ = progress(vₓ) · (1 + r_gait)

不前進就拿不到步態正收益，堵住站著與原地踏步；但早期正訊號稀薄，並容易讓 binary contact proxy 主導動作，造成頓腳、抖動與高能耗。

12 · Gait-only smooth gate

p=clip(vₓ/.3); g=p²(3−2p); r′gait=g·r_gait

只在低速削掉 gait 分，不動 alive、speed 與其他 reward。從零訓練會失去鷹架；從 03 checkpoint 微調則同時保留步態與移除 attractor。

Final recipe

兩階段 curriculum

25k 並不是「只訓練 25k」。它是接在 03 的 1M 預訓練後面，用較低學習率做小幅 reward 遷移。

Stage 0103 預訓練

1,000,000 steps。完整 legacy gait 分數提供站穩與探索步態的學習鷹架。

→
Stage 02切換 Gate

載入 actor / critics、清空 replay buffer、learning_starts=0、noise=.03。

→
Stage 0325k 早停

固定五項約束選 checkpoint。120k final 已發生速度漂移，不自動視為最佳。

總訓練量：1,000,000 + 25,000 = 1,025,000 steps。 25k 是微調甜蜜點，不是 undertraining。

What the failures taught us

最重要的不是哪個權重最大

03 的站立分數是鷹架，也是漏洞

它讓 cold start 先學會站穩；成熟 policy 卻不需要它。正確解法是 curriculum，不是從第一步就 gate。

代理指標會被 reward hacking

08 的 anti-phase 與 regularity 最漂亮，但 jerk、CoT 和肉眼觀感退步。binary contact 指標不能單獨當目標。

10 沒有隔離變因

legacy × forward gate 同時改了多個權重與結構，結果變差只能反證整組設計，不能單獨證明某一個旋鈕。

Final model 不等於 best model

12 從 25k 到 120k 速度誤差持續惡化；checkpoint 必須依預先定義約束選擇，不能自動拿最後一步。
